# Cut Studio — design and laser tools

Each tool has its own address, for example `/en/nesting` or `/ar/box-maker`. The interface is in English and Arabic. SVG, DXF and images are processed in the browser. CDR files are sent to a helper on this same computer, converted locally, then deleted from its temporary directory. No cloud conversion, account, API key or paid conversion service is used.

## CorelDRAW → Cut Studio → RDWorks

1. Choose a CDR, ASCII DXF or SVG file. In CorelDRAW or Illustrator, convert text to curves/outlines first. For SVG, include explicit physical dimensions and a viewBox.
2. Open Material nesting and import the artwork. For unitless DXF, open Units & import size and select its original units. For multipage CDR, select the page to import. The optional width override resizes the artwork deliberately.
3. Set the sheet size, copies, edge margin and spacing in millimetres. Disable rotation for grain-sensitive materials. Press **Arrange parts**.
4. Inspect the placed count and every sheet. Oversized parts and parts exceeding the processing time budget are explicitly reported and excluded from export.
5. Export each sheet as **DXF** for RDWorks, or **SVG** for editing in CorelDRAW/Illustrator.
6. In RDWorks, select millimetres during import and check the artwork dimensions. The **Workflow & file guide** includes a 100 × 100 mm reference square in both formats. Assign your own laser settings.

Native CDR, ASCII DXF and SVG input are supported. AI and PDF input remain unsupported. Exported files have not been imported into the user's desktop cutting programs; use the reference square to confirm actual scale there.

## The seven tools

| Tool | What it does | Output |
| --- | --- | --- |
| Material nesting | Packs closed contours using 0°, 90°, 180° and 270° rotations, optional rotation lock, spacing and multiple sheets | SVG / DXF, one sheet at a time |
| Image to vector | Thresholds raster logos, removes small black components, traces outer contours and holes, optionally simplifies outlines | SVG / DXF; send directly to nesting |
| Vector cleanup | Reports open contours, removes duplicate contours and optionally removes tiny closed contours | SVG / DXF; send to nesting |
| Resize & repeat | Scales the whole artwork page, including margins, and repeats rows/columns with spacing | SVG / DXF |
| Material cost | Calculates material, labour, machine cost and percentage overhead from your inputs | CSV estimate |
| Fit test | Makes a coupon with labelled slots around the supplied material thickness | SVG / DXF; CUT and ENGRAVE layers |
| Engraving prep | Adjusts brightness, contrast and inversion, then thresholds or dithers an image | Black-and-white PNG |

## Geometry and quality limits

### CDR import

- CDR input is limited to 10 MB. The bundled `cdr2xhtml` converter reads the actual vector document, rather than tracing an embedded preview. Conversion is limited to 30 seconds and 64 MB of output. Live text objects and embedded bitmaps are not cutting outlines: they are removed from the page and the import shows how many were skipped (convert text to curves in CorelDRAW to include it). One conversion runs at a time.
- Multipage documents expose a page selector; only the selected page enters the workspace. Paint gradients are removed from the converted cutting geometry; actual paths and transforms are preserved for the SVG importer. Text, bitmaps, clipping and unsupported effects are rejected with instructions to convert to plain curves.
- CDR version support depends on libcdr. An unsupported or damaged file receives an error; saving an older CDR version in CorelDRAW can help. This is not a claim of compatibility with every CorelDRAW feature/version.
- Solid-line defaults such as `stroke-dasharray: none` and a zero dash offset are accepted. Real dash patterns are not silently converted into continuous cutting lines.
- Requests are accepted only from the same-origin local toolkit; the server binds to loopback by default. Temporary file names are generated by the server, and files are removed after conversion. No shell is used to run the converter. CDR conversion is deliberately disabled on public hostnames.
- On another Windows x64 computer, install Python 3.14+ and run `python scripts/setup-cdr-runtime.py` from the project. This uses pinned, checksum-verified official MSYS2 runtime packages without running an installer. `CDR_CONVERTER_PATH` can point to an existing `cdr2xhtml` executable on other systems. The converter and its runtime DLLs must remain together.

### DXF import

- ASCII DXF supports LINE, R12 POLYLINE, LWPOLYLINE including bulges, CIRCLE, ARC, ELLIPSE, and positive-weight control-point SPLINE degrees 1–5. Source limits: 32 MB, 5,000 entities, 1,000,000 vertices (20,000 per curve).
- INSUNITS determines physical size. Unitless/unknown units require an explicit choice of millimetres, centimetres or inches. An explicit choice overrides the header. The optional target width deliberately rescales the design.
- The drawing is normalized to its geometry bounds with a top-left origin and downward screen Y; physical size is preserved. The original CAD page/margins are not retained. Curves are flattened with a 0.05 mm target, within the nesting engine's conservative 0.1 mm allowance.
- Fully enclosed closed contours are grouped with their enclosing piece to preserve holes during nesting. Open, intersecting and touching contours remain separate. This is geometric grouping, since DXF entities do not encode SVG-style compound paths.
- TEXT, MTEXT, ATTDEF and ATTRIB entities are ignored and reported. Binary DXF, INSERT/block references, hatches, dimensions, non-flat geometry, paper space, wide/fitted polylines and fit-point-only splines receive explicit errors. Expand/explode these objects into the supported flat geometry in your design program before importing.

### Box maker

- Box types: closed box (6 parts), open tray (5), lift-off lid (tray + lid + lid locator that sits inside the opening), sliding lid (lowered front wall, open-front slots in the side walls, lid stops at the back wall) and drawer (5-part sleeve, 5-part drawer tray, drawer face).
- Size is width x depth x height in mm, entered as the finished outside size or the usable inside size. Inside size adds the material and clearance each type needs (for example closed +2t per dimension; drawer width +4t+2 clearance).
- Engine: every part is a slab (an axis-aligned cuboid one thickness thin). Where slabs overlap, joint rules decide ownership: finger joints (odd count nearest the finger width, minimum 3, one-thickness inset only where a third part meets the corner), whole-overlap ownership (lid slots), through-tenons (dividers into walls) and half laps (crossing dividers). Corner cubes go to the higher-priority part (front/back, then sides, then bottom/top/lids, then dividers). Each part is traced from these cells, so every piece of material belongs to exactly one part; the tests check this for all types with and without dividers.
- Flat edges (glue, no fingers) can be switched per edge group: vertical corners, bottom edges, and top edges (closed box and drawer sleeve). A flat edge is a butt joint: front/back keep the overlap over the sides, and walls keep it over the bottom and top (which then sit inside the walls, e.g. a (W - 2t) x (D - 2t) bottom). Corner cubes follow the same butt-joint owners. On the sliding lid the side walls keep the back corners so the strip above the slot stays attached. Dividers keep their tenons.
- Dividers: rows (parallel to the front) and columns, up to 20 each, evenly spaced, crossing with half laps and locking into the walls with centred through-tenons. Their height stops below a lid with clearance.
- Kerf compensation (0-0.5 mm) grows outlines by half the kerf; holes shrink by the same amount. Clearance (0-2 mm, default 0.3) is the gap for lids, the drawer and slots.
- Extras: engraved part labels in a built-in single-stroke font (A-Z, 0-9) on the ENGRAVE layer, skipped and reported when a part has no clear space; hand holes (rounded slots) in the side walls; lid/drawer pull as a thumb hole or finger slot through the lid and locator or drawer face and drawer front; rounded corners only where no joint meets the corner; CNC dogbone reliefs (router bit radius, 0-5 mm) at every inside corner. Holes that would cut into an edge, joint or mortise give a named error.
- Views: flat layout (red cut, blue engrave) and an interactive 3D view (three.js, loaded only when opened) that extrudes each exported outline onto its slab, with drag to rotate, scroll to zoom and an explode slider. A parts list shows each part's size and hole count.
- Exports: SVG (red cut / blue engrave) and DXF (CUT / ENGRAVE layers); "Arrange on sheet" sends all parts, labels included, to Material nesting. No machine settings, living hinges or glue instructions are generated. Cut a test corner first.

### Shared geometry

- Each SVG geometry element becomes a separate nesting part. A compound path keeps its subpaths and holes together; groups supply transforms but do not bind separate elements into a part.
- Nesting uses outline collisions and conservative clearance. It does not place parts inside holes, perform common-line cuts, compensate kerf, optimize machine travel, or guarantee the global minimum number of sheets.
- Inside the toolkit, curves are held twice: as a polyline for nesting and previews, and, where the tool knows it, as the exact outline (lines, circular arcs and cubic Béziers). Nesting adds 0.1 mm to the sheet edge allowance and 0.201 mm to inter-part spacing.
- Exports keep real geometry. SVG is written with lines, arcs and Bézier curves. DXF stays R12 (read by RDWorks, LightBurn and CorelDRAW) and uses lines and arcs (polyline bulges); Bézier curves become arcs within 0.01 mm. A contour known only as a polyline (generated shapes, imported SVG or DXF) is fitted into lines and arcs within 0.02 mm at export, measured at its vertices; an arc may not bow more than 0.1 mm away from any original segment, so straight sides and polygons stay exact. A generated circle exports as two arcs, not hundreds of segments.
- Nesting supports up to 500 requested pieces. Collision tests use each part's outer outlines only (holes and inner engraving never touch another part; open paths outside every closed outline make the part use its convex hull). When those outlines exceed 8,000 nodes they are simplified in steps from 0.05 mm up to 2 mm, and twice the chosen tolerance is added to part spacing, so the exported full-detail parts still keep the requested spacing. The result reports the tolerance used. A worker keeps the interface responsive, supports cancellation and stops after 30 seconds. Internal search has an 18-second budget; reported partial results may have unplaced parts.
- SVG input is limited to 32 MB, 5,000 shapes, 50,000 elements and 1,000,000 vertices. Adaptive Bézier subdivision uses transformed millimetres with a 0.09 mm curve-to-segment bound; straight collinear reduction is exact. Live text (not converted to curves) is ignored and the import reports how many text objects were left out; a file containing only text is rejected. Standard design-program export boilerplate is accepted: the public DOCTYPE line, <style> class rules and inline styles limited to paint, dash, font and rendering-hint properties, @font-face blocks, embedded fonts and other content inside <defs>, editor metadata in foreign namespaces, and fill/stroke references to gradients in the same file. Dash patterns do not split the cut path. CSS that can change geometry (transform, display, clipping) is still rejected. Unsupported external resources, scripts, effects, clipping and embedded images are rejected. Common paths, primitives, compound subpaths and transforms are supported. Geometry coordinates must be unitless; root physical dimensions support mm, cm, in, pt, pc and px.
- Exported paths are cutting centerlines; SVG fill and stroke styling is not reproduced. Open paths remain open.
- DXF uses ASCII polylines, explicit closure flags, millimetre coordinates, a millimetre units header, and a vertical-axis conversion. Some CAD importers ignore unit hints, so confirm physical size after import.
- Image input is PNG/JPEG/WebP, up to 10 MB and 40 megapixels. It is downscaled to a maximum 768-pixel side for processing, with the resize shown in the UI. Transparent pixels are composited on white.
- Image tracing produces monochrome contours, not multicolour or centreline tracing. A zero simplification setting retains pixel boundaries (with exact collinear reduction). Higher settings approximate the contour and may change thin details. Preview before use.
- All traced contours initially form one artwork part; separate pieces in your vector editor if you want them independently nested.
- Vector cleanup repairs a file for cutting, and reports each change:
  - **Remove overlapping lines** (on by default): any stretch of cut line lying on another within 0.02 mm is removed from the later one, so it is cut once. This is the Delete Overlap step of RDWorks and LightBurn. A contour that loses part of itself becomes open paths.
  - **Join gaps up to** (0.1 mm by default, 0 to 10 mm): open paths whose ends are that close are joined, closest first; a path whose own ends meet is closed.
  - **Remove areas smaller than**: closed contours under the area are removed (this includes small holes).
  - **Reduce nodes** (on by default): contours are refitted into lines and arcs within 0.02 mm.
  Engraved lines are never changed.
- The cost calculator uses the selected currency as a label and performs no currency conversion. It does not infer prices, tax or profit.

## Development

The existing portfolio is preserved. `/tools` has its own root HTML layout, fonts and styles. Shared toolkit code is under `src/toolkit`; nesting and image processing run in browser workers. The local CDR helper uses a private libcdr runtime under `.tools/cdr`, downloaded from official MSYS2 packages with SHA-256 verification. It does not automate or modify the CorelDRAW application. See scripts/cdr-runtime-lock.json for exact package sources and hashes. npm scripts bind to 127.0.0.1 because CDR conversion is local-only.

```powershell
npm run dev
# Open http://localhost:3000/tools

npm run typecheck
npm run lint
npm run build
$env:PORTFOLIO_TEST_URL='http://localhost:3012'
# With npm run start -- --port 3012 running:
npx playwright test
```

Tests cover physical dimensions, transforms, malicious/unsupported SVGs, compound holes, tracing all 512 binary 3×3 patterns, collision/clearance, nesting accounting and placement quality, cleanup complexity, DXF closure/orientation, actual browser downloads, stale-result protection, and Arabic/mobile layouts. Existing portfolio regression tests run alongside the toolkit tests.

### Tracing, lettering and offset

- Image to vector, outline and colour modes: a loop that fits a circle within half the fitting error becomes a true circle, and a side between two corners that fits a straight line becomes one. Traced curves go to the laser tools and to DXF as curves, not as a 0.02 mm polyline.
- Image to vector, cut-out colour mode: every border between two colours is found once, on the cracks between pixels, and fitted once with its ends pinned where three or more colours meet. Each colour's outline is built from those shared borders, so neighbouring colours match exactly. The cut-line SVG and the DXF write each border once. Where a colour strip is thinner than the smoothing, its borders are refitted closer to the pixels until no two cross. **Remove the background** (on by default) leaves out the colour covering more than half of the picture's edge.
- Arabic lettering welds the glyph outlines with a vector union (Clipper2) at the final size, from outlines flattened within 0.005 mm, and refits the result within 0.01 mm.
- Contour & offset offsets vector artwork with Clipper2 using round joins (even-odd fill, so imported holes work whichever way they wind). Picture (sticker) input is still rasterised and traced, because there is no vector to offset.
- `npx jiti scripts/test-pack.ts` writes a machine test pack (box, gear, puzzle, traced logo in outline and cut-out modes, offset) as SVG and DXF into `test-pack/`.
